# Локальная подготовка PostgreSQL для TDD

Проверка 08.11.2026: localhost:5432 отвечает, но `psql -w` от имени
postgres требует пароль (`no password supplied`). Секретов у агента нет.
Учётные данные и данные версии SDD не читаются и не изменяются.

В обычном локальном PowerShell из корня проекта выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-database.ps1
```

psql запросит пароль администратора PostgreSQL, затем дважды новый пароль
роли `habit_tracker_tdd_app`. Ввод скрыт; не присылайте пароли в чат.
Если административная роль называется иначе, добавьте `-AdminRole имя`.
Политика выполнения меняется только для этого процесса PowerShell.

Скрипт создаёт только две базы `habit_tracker_tdd`, `habit_tracker_tdd_test`
и роль `habit_tracker_tdd_app` без административных прав. Существующие базы
не удаляются и не очищаются. При повторном запуске пароль роли задаётся
заново; при чужом владельце базы или административных правах существующей
роли выполнение останавливается. Скрипт не создаёт таблицы приложения.

Ожидаемый итог — две строки с именами этих баз и владельцем
`habit_tracker_tdd_app`. После выполнения сообщите только, что настройка
завершена, либо текст ошибки без секретов.

Этот скрипт пока проверен синтаксически как PowerShell, но не выполнен
с административным соединением. Создание баз и успешная аутентификация
на основном сервере не считаются подтверждёнными.

Обновление 09.11.2026: интеграционные тесты и GUI реализованы. Для TDD
автоматически создаётся временный кластер PostgreSQL 18.6 на свободном
loopback-порту со случайным паролем в памяти; он не требует пароля основного
сервера и удаляется после проверок. Это не настройка постоянного хранения
приложения на localhost:5432. После setup-database.ps1 запустите run.ps1
и введите заданный пароль роли скрытым вводом. Подробности — [RUN.md](RUN.md).
